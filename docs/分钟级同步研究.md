# 报文触发压力比对研究

当前方案为新报文触发识别，并使用历史画面缓存，不再独立定时视觉识别。变送器目前每 60 秒采集并上传，本机每 20 秒查询新增报文。保持一条摄像头 RTSP 长连接，每秒缓存 2 帧 JPEG，保留最近 120 秒，内存上限 64 MB。缓存仅在内存中，重启后需要重新积累。

## 处理流程

1. 厂家接口通过 afterTime 查询新报文，报文保存在本机独立缓存。
2. Python 检查未处理报文，只处理方案启用之后且晚于本次研究清除时间的报文。
3. 按报文 recvAt（厂家平台接收时间）选择时间差最小的缓存画面，默认容差 ±10 秒。
4. 有合适画面时执行一次单帧识别并保存原图。没有合适画面时记录“缺少对应历史画面”，不使用当前照片代替。
5. 结果记录 transmitterStamp，绑定原报文，不与邻近报文重新配对。相同报文使用稳定结果 ID，并通过持久化处理记录避免重复入库和重启后的重复消费。
6. 识别结果先发布到实时页面，再保存 Excel；Excel 写入失败不会丢失已发布的结果。

识别数值按用户要求直接解释为 MPa；变送器按单位码换算至 MPa。0～16 MPa 为当前量程。原 API 的 valueKpa 等字段名为兼容历史数据保留，当前单位由 meter.unit=MPa 指定。

## 时间依据与限制

recvAt 是厂家平台接收时间，缓存帧时间是本机接收该视频帧的时间，两者均不等于严格的设备采集时刻。该方案减少本机查询等待造成的额外错位，但仍有设备传输、视频传输及两端时钟差异。页面始终标注近似时间匹配。缓存未覆盖、报文太旧、取流中断等情况会如实显示，不补造成功读数。

## 控制与研究

启动采集恢复本机厂家查询与报文处理；暂停停止查询与识别，视频缓存保持连接。冻结展示只暂停页面刷新。清除会备份并开始新的研究时间边界，保留原始文件、Excel、照片、模型和设备设置；旧报文不重新触发。停止研究采集.cmd 可安全关闭取流进程。

页面周期设置控制变送器周期，支持 60～8640 整数秒，需等待设备同步。它不再控制视觉定时采样。容差支持 0～30 秒，且小于半个设备周期，用于历史选帧；调整后对新处理报文生效。历史结果绑定原报文并保留时间差，不能被重新分配给其他报文。

图表包含时间双曲线、偏差趋势、相关性散点。点击数据点可查看原图、时间差及识别质量。筛选范围影响图表、统计和 CSV/Excel 导出。导出包含报文编号及触发状态。识别失败、缺图、超量程、未知单位或超时数据不参与有效误差统计。

## 配置与文件

- config/pipeline.json 的 read.trigger_mode 为 transmitter。
- read.frame_cache_seconds、frame_cache_fps、frame_cache_max_mb 分别控制缓存时间、帧率和内存限制。
- read.trigger_activated_at 为方案启用边界，不要日常反复修改。
- config/live.json 的 recognitionMode 为 transmitter，pairingToleranceSeconds 控制选帧及比较容差。
- data/research/trigger-ledger.json 记录已处理报文；不要在保留旧缓存的情况下单独删除它。
- data/live/status.json 包含缓存帧数、内存用量及最早/最新帧时间。
- data/research/pipeline.log 与 pipeline-error.log 为运行日志。
