# 摄像头布置与高清取流

2026-10-22 已完成主码流取图测试，图片实际尺寸为 2560×1440。原设置为 640×360 子码流。更高分辨率保留更多原始像素，但不能修复失焦、反光、抖动或识别算法本身的错误。高清切换后还需要重新核对实际读数精度。

## 已设置的项目

| 项目 | 当前设置 |
|---|---|
| 摄像头 | TP-Link TL-IPC342-4 |
| 取流 | 主码流，实测 2560×1440 |
| 配置位置 | config/pipeline.json：camera.sub=false |
| JPEG 缓存 | read.frame_cache_seconds=120，frame_cache_fps=2，frame_cache_max_mb=256 |
| 识别触发 | 一条新变送器报文触发一次识别 |

每秒缓存两张图用于按时间选帧，与摄像头编码帧率、变送器每分钟上报一次分别设置。高清图片体积与场景有关，256 MB 是缓存中的 JPEG 字节上限，不是整个识别进程的总内存上限。检查 data/live/status.json 中 newestFrameAt-oldestFrameAt，稳定运行后应接近 120 秒。

## 布置顺序

1. 保持前端“暂停采集”，调整期间不要采集正式实验数据。暂停时视频缓存仍在运行。
2. 清洁镜头和表盘玻璃，确认保护膜已去除。用固定支架分别固定摄像头和压力表，避免手持和桌面晃动。
3. 让镜头正对表盘中心，尽量让镜头所在平面与表盘平行。先保证画面中的表盘接近圆形、上下左右刻度完整；不要为躲反光把摄像头大幅斜置。
4. 调整实际距离，使表盘位于画面中央、占画面高度约 60%～80%，四周留边。以 1440 像素高的原图估算，对应表盘直径约 860～1150 像素。这是本项目的初始布置目标，不是摄像头的硬性指标。
5. 距离以原图清晰为准。过近可能超出镜头可清晰成像的范围；如果靠近后更模糊，应后退。镜头是否支持调焦，以实际镜头和厂家说明为准，不要直接拧动不明部件。数字放大无法增加真实刻度细节。
6. 移走或遮住表盘背后的明亮显示器、窗户等光源。先用均匀环境光；需要补光时，从表盘侧前方斜照，使用柔和散射光，调整灯的位置，让亮斑避开指针和刻度。优先移动光源，保持摄像头正对表盘。
7. 若需要进入摄像头管理界面，通过现有厂家工具或可用的配置页面检查：主码流 2560×1440、维持已经验证可解码的 H.264、画质选择较高档。具体菜单及码率范围以实际设备为准。先改善布置和光线，再调整曝光、锐度和降噪；不要直接把这些滑块拉到最大。
8. 在原图 100% 比例查看指针尖端、最小刻度和表盘数字。若时间水印很锐利但表盘模糊，说明高分辨率已经输出，仍要检查光学对焦、距离、抖动等问题。水印清楚不能证明表盘已经对焦。
9. 布置稳定后再点击“启动采集”，等待下一条新报文，在前端查看其对应照片、视觉时间、平台时间和选帧时间差。不要用调整前的历史照片评价当前布置。
10. 在多个稳定压力点人工读表，分别记录视觉读数和变送器读数。两路数据差异还包含仪表差异和近似同步误差，不能只据此认定模型读错。

## 验收重点

- 原始 JPEG 为 2560×1440，完整包含表盘。
- 表盘中心和四周的小刻度均能分辨，指针尖端没有明显重影。
- 玻璃反光不遮挡指针和两端基准刻度。
- 固定后连续照片中表盘位置不明显变化。
- 缓存最新帧时间持续前进，稳定后的实际覆盖时长接近 120 秒。
- 正式识别用多组人工真值检查，不因模型显示“ok”就认定精度合格。

## 后续软件适配

现有识别器仍会先用整图定位，再进行自动裁切与 640 尺寸模型推理；高清整图并不保证模型有效利用所有像素。2026-10-22 已修复摄像头高清帧因模型针长超过 700 像素而绕过增强定位的问题，实时单帧及连拍均明确关闭旧离线大图路径。如果固定布置后仍有中心定位漂移，下一步适合增加人工固定表盘 ROI，在原始高清画面中先裁表盘再识别。此功能尚未加入，不能把当前自动裁切当成人工固定 ROI。

此前精度分析报告基于当时的 640×360 图片，其离线数值属于历史诊断，不能当成切换高清后的精度测试结果。
